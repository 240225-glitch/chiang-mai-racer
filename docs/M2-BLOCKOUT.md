# M2 清迈护城河赛道：开发原型

2026-10-31。状态：**OSM 实际外圈道路中心线已接入；路宽/城门仍为游戏示意，水面已导入 OSM 19 块护城河多边形，现场路段核验和真实 GPU 试玩待完成**。

## 本轮已完成

- tools/osm_outer_ring.py：从 OSM API XML 按节点和单行方向拼接 90 条 way，得 6,497.5 m 路线；tools/build_moat_blockout.py 默认生成重采样后的 6,492.2 m、650 点 OSM 道路中心线，--schematic 可生成旧尺寸原型。
- assets/tracks/chiangmai-moat/road.json：5 个合并网格，4,274 个三角面，含 OSM 道路中心线生成的路面、示意路肩、19 块 OSM 护城河水面及检查点拱门。
- assets/tracks/chiangmai-moat/route.json 和 route-data.js：路线元数据，供分析器与几何生成使用。
- tools/moat-preview.html：Three.js r50dev WebGL 预览。
- tools/osm_city_gates.py：从同一 OSM XML 快照核实并提取 Tha Phae、Chiang Mai、Suan Dok、Chang Phueak 四个 historic=city_gate 节点，坐标/OSM node ID 记录在 source-gates-osm.geojson；四个检查点现按最近赛道点与历史城门对齐，起跑点重新锚定 Tha Phae 门附近。另以单个合并网格生成四组红砖色城门/短墙低模示意体，**不是实测建筑模型**。
- bkcore/hexgl/MoatCollision.js：基于路段空间网格查询的 14 米碰撞走廊、4 个依序触发的检查点和 3 个加速带。
- bkcore/hexgl/tracks/ChiangMaiMoat.js：复用旧游戏的场景、HUD、车辆系统，但只加载 M2 实际使用的资源；提供可选入口 ?track=moat，默认保留原 Cityscape。
- 专用速度：休闲最高 0.62 米/帧，竞技最高 0.82 米/帧，HUD 使用近似 km/h 换算。实际圈速待测试。

## 重要限制

**赛道道路中心线已由 2026-10-31 的 OSM 官方 API 快照提取**，但尚未人工逐段核对与现场核验；统一 14m 路宽与四组门框仍是游戏示意；护城河水面已采用 OSM 19 块真实绘制的多边形，但尚无桥梁/岸墙或现场核验。当前 M2 使用精简资源清单：低画质 15 项加载资源（原 Cityscape 28 项），较高画质 17 项，不再请求旧赛道几何/分析 PNG。仍复用飞船、天空盒、HUD 和音频资源。

已通过 Chrome 148 无 GPU headless SwiftShader 的 WebGL 冒烟测试（现为 8 场景）：预览加载、单人前进和浏览器模拟一圈完整计圈、双人两个独立控制/HUD/检查点、高及极高画质、默认 Cityscape、资源失败回退均通过。仍缺真实 GPU/用户设备的完整驾驶体验、手动绕圈、氮气手感和帧率验收。

在线 gta.jizhang.org 是另一套游戏产物，不应覆盖。

## 2026-10-31 续轮：导入质量和斜向起跑修复

- **已确认的导入缺陷**：旧导入器允许闭环首尾相距 20 米，悄悄用直线补路；自交、错经纬度与不在古城周边的环线也可能通过。现将闭合容差缩小到 0.1 米，拒绝自交、重复极短线段、无效经纬度、偏离古城 3 km 的输入，并限制离线校验规模，防止病态数据卡住导入。
- **已确认的赛道朝向缺陷**：旧起跑方向硬编码为 +Z，双人始终沿世界 X 分列；导入斜向道路后车辆会横着冲出赛道，双人可能前后排列。现在根据起点切线生成 yaw 和完整 quaternion，兼容旧版 Cityscape 的缺省 w=1；双人相对道路法线并排起跑。
- **检查点可视模型**：旧版只按世界 X/Z 轴摆放拱门，斜向道路会摆歪；现按局部道路法线旋转柱子和横梁。仍是示意模型而非真实城门。
- Python 几何回归增至 10 项，Node 三套回归通过，Chrome 148 headless SwiftShader 8 场景通过：新增内存中旋转 45° 的合成赛道，验证双人法线并排、真实物理前进方向与无 WebGL 错误；测试不修改仓库资产。
- 真实 OSM 数据依旧未获取：本轮 Overpass kumi.systems、private.coffee、overpass-api.de 均超时，nchc.org.tw DNS 解析失败。未将示意路线伪装成实测地图。

仍待验证：实际 GPU 性能、完整真实驾驶绕圈与转弯手感、真实 OSM 道路和四城门经纬度。

## 2026-10-31 急弯驾驶参数

OSM 中心线第 400 点相邻段转角约 55.388°，第 401 点约 33.972°；原 HexGL 的 ShipControls 构造默认 0.005 rad/frame，但实际比赛中由 tweakShipControls 覆盖为普通难度 0.019、困难难度 0.021；清迈窄赛道需要进一步调校。现在仅清迈赛道车辆采用普通转向 0.024、手刹转向增量 0.030（旧版内部帧参数），并新增真实 WebGL ShipControls.update 转向测试；Cityscape 仍使用旧值。此调整仅验证转向幅度，**尚未验证真实玩家能够不碰撞驶过整组急弯**。真实 GPU、完整手动整圈与弯道手感仍未验收。

- 已补充 **实际物理沿路驾驶急弯** 的自动测试：Chrome SwiftShader 中，测试控制器从 index 392 驶过 55°+34° 弯道到 index >=408，301 物理帧、3 次路肩回弹，无跌落/损毁；与手动驾驶/完整一圈/GPU 实机仍有差距。浏览器冒烟累计 11/11。

### 2026-10-31 M3 桥梁距离算法修复

- 修复桥梁候选提取的**漏检风险**：此前只检查 OSM 道路节点和相邻节点中点到水体的距离；很长的线段可能从窄水面穿过，而三个采样点均远离水面，导致漏掉真实候选。现在计算完整道路每条线段到水体多边形边界的最小距离，并处理相交/线段在水内情况。
- 新增合成 200m 长线段穿越 2m 水面的回归，旧采样法会漏检；实际 2026-10-31 OSM 快照重算后仍是 **13 条近水候选、7 条 footway 几何跨水、6 条仅近水**，其中 3 条非跨水道路距离从 8.58→8.56m、5.33→5.30m、11.00→10.87m；way IDs 不变。
