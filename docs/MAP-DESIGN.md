# 清迈古城环线 · 赛道设计

> 版本：v0.1（blockout 前）
> 赛道 ID：`chiangmai-moat`

## 1. 为什么选这条线

清迈古城（Chiang Mai Old City）是一个近似正方形的旧城，四周由护城河与城墙遗迹包围。
护城河两侧各有一条单行道，外圈顺时针、内圈逆时针，形成一个天然闭环。

| 参数 | 数值 |
| --- | --- |
| 环线长度 | **约 6.54 km** |
| 形状 | 近似正方形 |
| 中心坐标 | `18.7883, 98.9855` |
| Tha Phae Gate（东门） | `18.7877, 98.9933` |
| 古城核心 bbox | `18.776, 98.974, 18.800, 99.001` |
| 地形 | 基本平坦，约 305–315 m 海拔 |
| 建筑 way 数量 | 约 **10,694**（Overpass，2026-10-30） |

优点：

- 天然闭环，不需要凭空设计赛道形状。
- 地标密集，视觉辨识度高。
- 平坦地形，适合现有街机物理。
- 1 / 3 / 5 圈制与现有系统直接匹配。

## 2. 赛道走向

**起终点**：Tha Phae Gate（东门）外侧，顺时针发车。

```text
        North Gate (Chang Phueak)
                 ▲
                 │
West Gate ───────┼───────► East Gate / Start-Finish
(Suan Dok)       │         (Tha Phae)
                 ▼
         South Gate (Chiang Mai)
```

- 使用**外圈道路**作为主赛线，顺时针。
- 内圈道路保留为视觉与缓冲区，不参与计时。
- 四个 90° 城门弯是主要超车点，建议圆角半径 **25–35 m**。
- 直道段可设置 2–3 条加速带。
- 起点后方留 80–120 m 发车区，双人并排。

### 分段检查点

| 分段 | 位置 | 作用 |
| --- | --- | --- |
| S1 / 起终点 | Tha Phae Gate | 计圈、发车 |
| S2 | Chiang Mai Gate（南门） | 防止抄近路 |
| S3 | Suan Dok Gate（西门） | 防止抄近路 |
| S4 | Chang Phueak Gate（北门） | 防止抄近路 |

> 现有 `Gameplay.js` 已有检查点/圈数逻辑，优先复用，不重写。

## 3. 尺度与路面

| 项目 | 设计值 | 说明 |
| --- | --- | --- |
| 世界单位 | 1 unit = 1 m | 与真实坐标一致 |
| 赛道长度 | 6,540 m ± 3% | 以 OSM 中心线为准 |
| 可行驶宽度 | **12–14 m** | 真实道路较窄，为超车与双人并排适当加宽 |
| 路肩 | 1.5–2 m | 视觉缓冲 |
| 护城河宽度 | 约 18–22 m | 按 OSM 水系简化 |
| 城墙高度 | 约 6–8 m | 遗迹段 + 程序化补全 |
| 弯道圆角 | 25–35 m | 避免 90° 死弯 |
| 单圈参考时间 | 2:30–3:30 | 取决于车辆极速 |

**原则**：视觉上保留「两侧单行 + 护城河」的真实结构，但比赛用路面适当加宽，避免高速会车空间不足。

## 4. 地标与视觉锚点

| 地标 | 相对位置 | 处理方式 |
| --- | --- | --- |
| Tha Phae Gate | 东侧 | 起点门 + 地标，程序化重建 |
| Wat Chedi Luang | 城内中西部 | 接入 Sketchfab 低模（2,151 tris） |
| Wat Chiang Man | 城内东北 | 简化重建或高模减面 |
| Wat Phra Singh | 城内西部 | 简化重建，屋顶剪影 |
| Chiang Mai Gate | 南侧 | 程序化城门 |
| Suan Dok Gate | 西侧 | 程序化城门 |
| Chang Phueak Gate | 北侧 | 程序化城门 |
| Doi Suthep | 城西远景 | 山体剪影 + 寺庙轮廓，不进入碰撞 |

> 具体坐标在 OSM 提取阶段统一确认，避免手工抄错。

### 视觉风格

- **低多边形 + 暖色 Lanna 色调**：陶土红、柚木棕、金色寺顶、热带绿。
- 贴图尽量少：顶点色 + 1–2 张 atlas。
- 护城河水面用简单半透明材质 + 轻微流动 UV。
- 远景用雾 + 山体剪影，避免高面数植被。
- 招牌、电线、灯笼用贴图面片，不建实体。

## 5. 建筑处理策略

10,694 栋建筑不能直接全部导入。

**分层策略**：

| 层级 | 范围 | 细节 |
| --- | --- | --- |
| L0 近景 | 距赛道 0–30 m | 完整立面、屋顶、招牌 |
| L1 中景 | 30–80 m | 简化立面 + 屋顶色块 |
| L2 远景 | 80 m 以外 | 合并成街区体块，仅保留屋顶轮廓 |
| L3 城外 | 护城河外侧 | 低模体块 + 树木 |

**合并规则**：

- 按 200 m × 200 m 区块切分。
- 每个区块按材质合并成 1–3 个 mesh。
- 目标：全场景 draw call < 300。
- 不使用实时阴影；AO 烘焙到顶点色或贴图。

## 6. 数据与制作管线

```text
Overpass API
  └─ 提取 highways / buildings / water / barriers / landuse
       └─ OSM2World 导出 OBJ / glTF
            └─ Blender 清理、减面、合并、烘焙
                 └─ 按区块导出 OBJ
                      └─ tools/obj2json.py
                           └─ 运行时 JSON + PNG
```

## 7. 碰撞与边界

- 赛道碰撞用**中心线 + 左右边界**的走廊模型，不用逐面碰撞。
- 护城河一侧：不可穿越护栏。
- 建筑一侧：路缘 + 建筑体块。
- 城门：可通行门洞 + 两侧墙柱。
- 双人模式：两名玩家共享同一碰撞世界，各自独立车辆状态。

**简化原则**：碰撞体只覆盖赛道走廊与城门，城内建筑不参与碰撞。

## 8. 性能预算

| 指标 | 目标 |
| --- | --- |
| draw call | < 300 |
| 可见三角形 | < 500k |
| 贴图显存 | < 128 MB |
| 中画质帧率 | 60 fps（集成显卡笔记本） |
| 低画质帧率 | 30 fps |
| 首次加载 | < 10 s（本地） |

**旧引擎限制**：

- 没有 `InstancedMesh`，所有重复元素必须合并或复用几何体。
- 没有现代 PBR，材质用 `MeshLambertMaterial` / `MeshPhongMaterial`。
- 没有 glTF 加载器，资产必须离线转换。
